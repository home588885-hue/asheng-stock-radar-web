# 阿勝雷達 vNext 核心評估及三區切換閘門（研究分支）

> 2026-10-22。**這份文件與 SQL 只用於研究，沒有啟用任何新買點，也沒有改動正式站。**

## 既有正式模型位置

- GitHub Pages: `admin.html` 為唯一正式前端；`index.html` 只轉址。
- Supabase `spring-swallow-analyze` 是模型來源，`spring-swallow-picks` / `spring-swallow-v5-picks` 等既有 API 對前端供應資料。
- 發動前／進場雷達／已買進必須消費相容的同一版模型與風控狀態；持股真實成本優先，絕不將未授權成本的公開掃描訊號直接變成加碼。
- 選股原本 MA10／MA20／MA60、存活 12 分鐘與 C 有效成交、-5% 停損、+5% 保本、+10% 停利、禁止攤平、最長持有 30 日的硬性風控不可在沒有完整驗收前移除。

## 已有功能，不要重複實作

正式 `spring-swallow-analyze` v52 已在 `metrics.fundamental_blend` 提供：
1. 近三個月營收年增率 >20%
2. 毛利率連兩季改善
3. 營業現金流為正
4. 外資十日買超
5. 放量站回 MA20

季度財報只對部分候選股讀取，以降低 FinMind / S 流量；這些值目前是 **觀察／品質訊息，不是正式交易放行閘門**。

2026-10-20~22 資料庫實測：635 筆掃描，449 筆有 fundamental_blend，173 筆營收條件通過，毛利／現金流各僅 1 筆，全五條件通過 0 筆。因此不得將全五條件設為硬篩選，也不能把資料缺值視為財務劣質。

## 本次經驗研究

只讀 SQL：`diagnostics/core-vnext-readonly-evidence-20261022.sql`。

比較 `spring_swallow_v5_research_events` 的 FIRST_BREAKOUT 各年歷史訊號，至少 1,000 張成交量，以及營收、MA60 斜率、相對強勢、近十日波動的預先指定條件。

結果指向「營收成長＋趨勢＋相對強勢」是候選研究方向，但：
- 2022 年報酬為負；2025、2026 年固定持有 20 日表現較佳，但未證明實際成交扣費後正報酬。
- 大量訊號於前十日觸及 -5%，固定持有的正報酬可能根本無法實現。
- 現有 V5 訊號含事後研究生成及多重重疊入場，2025/2026 年亦已被反覆查看，不是乾淨的 untouched holdout。
- 本次**未驗證新模型在每筆 5,000 元、總資金 60,000 元的資金限制下有正的逐筆淨報酬**。

## 替換上線的硬性驗收條件

1. **資料時間閘門**：營收、季度毛利和營業現金流的發布日不得晚於訊號日；缺資料設 `unverified`，不能默默當成買點或淘汰舊追蹤股。
2. **逐日成交**：訊號日後第一個可成交價格進場；逐日 OHLC 模擬 -5% 硬停損、+5% 保本及動態移動、+10% 全出、最長 30 日、現有 MA20 出場；碰到停利與停損同日、順序不明時取不利成交；跳空依可成交開盤價。
3. **成本**：股票手續費雙邊、賣出 0.3% 證交稅、滑價，5,000 元小額交易的最低手續費另行保守估算；不以固定持有 `r20` 代替已實現淨利。
4. **資金**：每筆投資 5,000 元、上限 60,000 元；同一股持股期間不得重複開倉或虧損加碼；現金不足拒絕新倉；結果需含勝率、平均淨報酬、最大回撤、年度報酬、交易筆數、淘汰筆數。
5. **時間驗證**：2022–2024 開發、2025 歷史檢驗、2026 只能做已接觸資料的回顧；仍需要未參與調參的新期間／前瞻觀察才可聲稱穩定樣本外。
6. **配對優越性**：用同期間、同資料、同成交假設與同資金比較舊正式模型；新模型扣費淨利必須 >0，且勝過基準，不可只追求勝率；負向市場須有明確防守。
7. **單一新模型出口**：只有驗收通過，才能用版本化的新 `model_generation` 跟單一 trade-decision API 供應三區；前端不能每區自行再算不同的提示。
8. **相容性與回滾**：保留正式原持股與成本、舊歷史追蹤；舊策略先停用新訊號，驗證後才停用退役執行器，不直接刪歷史資料或使舊 API 復活。
9. **零新增資源**：不得增加原有每日 450 次掃描計數、每批 20、股票月 120,000 自訂權重計數、預留 20,000、Supabase / C 盤中頻率與 LINE／房產網站負荷。
10. **正式驗收**：運行 `node diagnostics/radar-regression-gates.js`，加上正式三區手機/桌機端對端、API 模型簽章、一致狀態、GitHub Pages 部署與真實已授權 C 成交驗證。測試通過才能合併與部署。

**決策：截至本研究分支建立日，上線條件尚未滿足。正式 main、Supabase Edge Functions、PWA 與持股資料保持不變。**
