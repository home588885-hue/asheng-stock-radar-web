# asheng-stock-radar-web

阿勝底部起漲雷達的獨立 GitHub Pages 前台，連接既有 Supabase。

- 管理員：`admin.html`，使用現有 Supabase 管理員帳號。
- 會員：`member.html`，使用現有會員帳號與權限。
- 前台來源：既有 `asheng-radar-member-web` v167 / member-v165，包含既有管理員會員管理與持股 API。
- 持股資料、MA10／MA20／MA60 選股模型、房產同步及 LINE 均不由此專案部署。
- 不含管理員持股識別碼、service-role 金鑰或會員資料。
- Supabase SDK 固定為 2.117.3。

## 最新使用方式（2026-10-09）

- 選股模型使用 MA10／MA20／MA60 與既有量價、籌碼和風險規則，不變更任何持股與會員權限。
- 交易日台灣時間 21:00～21:55 啟動分批選股更新，掃描以最近可取得的完整交易日日 K 為基準。排程有用量保護，部分候選可能較晚完成，不能宣稱每晚所有股票都已更新。
- 「發動前」、「進場雷達」和一般候選畫面只讀取最近模型快照，盤中不更新即時報價，不在前台呼叫個股模型分析器。
- 「🔔 新買點提醒」只比較既有進場雷達快照中通過原本優先風險檢查的 🟠 小量試單候選與 🟢 突破確認候選。首次使用建立基準，後續同股票／同模型日／同級別不重複提醒；這是站內提示，不會在網頁關閉後推播，也不是盤中即時買進訊號。
- 為節省額度，既有掃描提交狀態查詢從每 30 秒改為約每 5 分鐘一次，且只在交易日 20:55～22:10 的夜間更新時段、頁面位於前景時執行；其他時段只在進站或手動重新整理時載入既有快照。
- 「已買進」平常盤中不持續抓報價；交易日 13:00～13:29 才啟動收盤前低頻量價確認，約每 3 分鐘取樣一次，搭配 MA20 與 12 分鐘存活提示續抱／警戒／減碼／出清警戒。13:30 後停止盤中行情請求。
- 收盤前量價取樣不代表 MA10／MA20／MA60、KD、MACD 等技術模型盤中重算；完整模型仍在交易日晚上 9 點後分批更新。
- 管理員及會員入口的「📘 新會員先看｜3分鐘看懂雷達」已同步更新。
- 夜間選股服務：Supabase `asheng-stock-scan-runner`，排程 `asheng-stock-scanner-supabase-standby`。本前台仍由 GitHub Pages 提供。
- 房產物件與照片同步、LINE 自動對話均不屬於這次調整範圍。

## 選股品質稽核（2026-10-09）

- **漏抓分析**：每次既有夜間掃描提交時，若完整日 K 模型有「可辨識的首根起漲」會在私人資料表 `private.stock_launch_detection_audit` 留下起漲模型日、首次看到它的掃描日期、相差幾個交易日，以及當時的基本風險篩選原因。這是**離線模型快照稽核**，不是 09:00～13:30 盤中的即時漏抓率。
- 歷史既有快照先建立 33 筆回溯基準，標示為 `historical_baseline_unverified`。絕不可將當中「起漲後才有的快照」直接認定為當時系統漏抓。
- **模擬持股交易績效**：既有掃描器取得的日 K 歷史同步讓資料庫用來結算 `private.stock_learning_observations` 的 5／10／20 日表現、30 交易日模擬交易報酬，以及以收盤價計算的最大回撤。完整歷史陣列會在寫入公開掃描表前剔除，無額外行情 API 呼叫。
- 30 日模擬假設：訊號次日開盤買入；收盤達 +20% 時，次日開盤賣出三分之一；收盤跌破 MA20 時，次日開盤賣出剩餘部位；未觸發出場者第 30 交易日收盤結束；基本成本假設買進 0.1425%、賣出 0.4425%，**未估滑價、最低手續費、實際成交限制**，因此不是個人的實盤成交績效。
- 目前真實學習樣本仍不足，既有權重與 MA10／MA20／MA60 核心模型鎖定不變；上列稽核只協助檢討，不直接放寬進場條件。需後續真實資料才可判斷有無改善，亦不加開掃描排程。
